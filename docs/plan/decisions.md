| G39 | `HttpRequest` is stricter than design section 12.2 in five places: a header name given twice in another case is refused, also inside the plain or the secret headers alone; a header name must be a string, so a name of digits only is refused; a secret header value with a line break is refused; the URL may hold only visible ASCII characters and no backslash; and the part between `://` and the first `/` or `?` must be a host of letters, digits, dots, hyphens and underscores that starts and ends with a letter or digit (an underscore is allowed because a customer's own server is often reached by a container service name such as `my_service`), or an IPv6 address in brackets, followed by at most `:` and a port from 1 to 65535. So no percent-encoding, trailing dot, second colon, empty port, open bracket or IPv6 zone in the host. The constructor takes the timeout before the body, because the body has a default and the timeout has none; the URL, both header lists and the body are sensitive parameters. Why: a PSR-7 message keeps one value per name without case, so a second one would be sent differently from what the report shows; a line break in a key is a header injection; a URL with a backslash, a control character or an encoded character in its host is read as different hosts by different clients (LR-29). | proposed |
| G40 | The PSR-18 bridge fills four gaps of design section 12.5. (1) A request the host's PSR-7 classes refuse to build is the failure `blocked` and nothing is sent. (2) Every exception of the client, of the response or of its body, also one PSR-18 does not name and also one that is not a `RuntimeException`, is `connection_failed` and is neither chained nor copied; a body that cannot say whether it has ended is broken, not complete. (3) An `Error` of the client or of its message classes (a fault in code, not a failure of the connection) never passes through: the bridge throws a new plain `\Error` with the fixed text "The HTTP client or its message classes failed with an error of class X.", not chained, so no frame of the client with the request in it survives; it is an `\Error` and not a `TransportException` so that nothing retries it and nothing maps it to a reason. An error class that implements the PSR-18 client exception stays `connection_failed`. (4) A response that breaks the rules of the library's own response (a status outside 100 to 599, a header value that is no text, an empty header name) is `connection_failed` and its body is closed; a body that gives nothing three reads in a row without ending is `connection_failed` too. Why: the refusal of a PSR-7 class can quote the header value, and the trace of anything thrown inside the client holds the request with the revealed headers (LR-26); it is the host's classes saying no (G31); a read that returns nothing for ever would hang the call where no deadline is checked. | proposed |

| G42 | `BearerToken` does not show its supplier and is the one place that calls it; keys and tokens that a client would change on the way are refused. (1) The supplier is not a public field `$tokens` as design section 11.2 lists it: it is kept as `Secret` keeps its value (G38), and the adapter base gets a token through `BearerToken::token(): Secret`, which asks the supplier at that moment and keeps nothing. (2) An `\Exception` of the supplier is caught there and replaced by the new `Contract\Credentials\TokenSupplierFailed` (a final `\RuntimeException`, built only by the library, not chained) with the fixed text "The token supplier failed with an exception of class X."; a token that is refused under (4), and so also an empty one, gives the same class with its own fixed text. The adapter base (LG-07) catches exactly that class around `token()` and turns it into the gateway exception `credentials_rejected` of section 7.3, not retried; it does not copy the text into a detail or an event, because the class name of a host can name a vendor. (3) An `\Error` of the supplier (a fault in the host's code, such as a `TypeError`) is no failed sign-in: as in the bridge (G40) a new plain `\Error` with the fixed text "The token supplier failed with an error of class X." is thrown, not chained, so nothing maps or retries it. (4) `BearerKey` and `HeaderKey` take the key as a string in their constructor and wrap it there. A key, and a token from the supplier, is refused when it is empty, holds a byte below 0x20 or the byte 0x7F (so a line break, a tab, a null byte), or starts or ends with a space; bytes 0x80 to 0xFF are kept. The refusal never holds the value. Why: the supplier is the host's class and may hold a client secret or a kept token in a plain property, which every dump of the credential (and of a gateway that holds it) would print (LR-26); its exception can hold the token in its message and its trace, so it must not get past the one call site; a broad catch in the adapter base could swallow a gateway or transport exception, a dedicated class cannot; PSR-7 message classes trim a header value, so a key with a space at its end would be sent without it while `secrets()` gave it with it, and the host's redactor would then miss the key in a log; the design gives the fields but no constructor and no validation. | proposed |
| G43 | The pattern of a preset field is a regular expression without delimiters, and the library anchors it: a value must match from its first to its last character. A value that fills a `{key}` placeholder of the default base URL must besides hold only letters, digits and `. _ ~ -`, whatever its pattern allows, may not be `.` or `..`, and the filled address is checked again as an address; otherwise `not_configured`, naming the key. A preset is refused when a placeholder in the host of its default base URL is not followed, after at most the rest of its label, by a dot and a fixed domain of two labels or more: `https://{resource}.example.test/` and `https://{region}-api.example.test/` are allowed, `https://api.example.test{x}`, `https://{x}/v1` and `https://{x}.test` are refused, so a setting can never choose the registrable domain. A required field with an empty value counts as missing. Why: design section 13.1 says "a regular expression the value must match" and relies on the pattern alone; a pattern without anchors would let a setting such as `other.example.org/` move every request to another host (LR-29), and a preset can be written outside the library (G34). | proposed |
| G44 | The adapter base differs from the sketch of design section 13.4 in these places (the section allows it). (1) It is an abstract readonly class with a final constructor, so every adapter is readonly and is built the one way the factory builds it; the five checks of section 13.3 run in that constructor (through `GatewayFactory::resolveBaseUrl`), so a gateway built without the factory is checked the same way. Credentials of a class other than the four of the library are refused there as `not_configured`: the base could not send them. (2) An adapter reaches the preset (`$this->preset`) and one setting of the customer by its key (`setting()`); the configuration with the clock, the observer and the retry policy, the credentials and the transport are private to the base. (3) `capabilities()` is final and checks the model name; the adapter writes `modelCapabilities()`. (4) `completionRequest()` and `modelsRequest()` give the request without sign-in; the base adds the sign-in header and the time left for every attempt, and refuses (a `LogicException`, nothing is sent) a request whose address does not start with the resolved base URL. `modelsRequest()` gives null where the models cannot be listed. (5) An adapter builds its answer with `answer()` and its own errors with `failure()`; the base fills in the trace id, the attempts, the status, the latency and the structured result, also for an error raised in `modelCapabilities()`. An error an adapter raises while it reads a response is never retried. A provider code or a detail that holds a credential anywhere in it (a key of `secrets()` or the token in use, compared without case) is dropped whole. (6) `retryAfterSeconds()` is a third hook next to `providerCode()` and `refineReason()`, for a wait a format documents outside the `Retry-After` header. (7) An exception an adapter throws while it reads a response becomes `provider_error` with a fixed detail; while it reads a failed response it means "no code, no wait, the reason of the status". An `\Error` there, and a value from `readStream()` that is no stream event, is a fault in code: the attempt is reported as finished, then a new plain `\Error` with a fixed text (class, file name, line) is thrown once, not chained, as in the bridge (G40). (8) The structured check of section 10 is not a hook: its place is marked in the base, which will call the checker itself; an adapter that gets the structured answer its own way hands the result to `answer()`. Why: the request value needs a timeout and secret headers that only the base knows per attempt; a readonly class cannot keep state between calls (LR-01); what an outside adapter can reach is a promise from the first release (G34), so it is kept small; the exception of an adapter can quote the body it could not read, and its trace holds that body, and a provider can repeat a key inside a longer code (LR-26). | proposed |
| G45 | Details the design leaves open, as built. A status below 200 is `provider_error`, not retried. A stream that fails after the response began carries the status of that response in its error. The deadline of a stream is checked when a chunk arrives: a chunk that arrives after it ends the stream as `timeout`, also when it would have been the last. A wait from the provider counts for `rate_limited` and `unavailable`; in the error it is rounded up to whole seconds and capped at 2147483647. `Retry-After` is read as seconds (a fraction is accepted) or as an IMF-fixdate that exists (31 February is not rolled over); any other form is treated as not given. A token supplier is asked after the check that time is left, and its time counts against the call. The time left for an attempt is computed before the "before" report, so a slow observer can make a call overrun by its own time. An attempt of a stream that the caller abandons is reported as succeeded, with what was read. An exception of a transport that is not a `TransportException` passes unchanged, after the attempt is reported as a transport error (`connection_failed`, no retry). Known limit: the bytes of a stream are kept whole for the report of the attempt (section 12.6), without a cap on their size; only the deadline bounds them. Why: each is the reading that keeps the eight reasons and the "retried" column of section 7.3 unchanged. | proposed |
| G46 | The event reader gives an event that is not closed by a blank line when the body ends, and takes a last line without a line end as a line. | G48 | The rules that several values share (trace id, model name, provider code, timeout, HTTP token) are written once, in `Contract\Internal\Rules`: a final class with static methods that only answer yes or no (or give the cleaned code), marked `@internal`, without state. `Request`, `Answer`, `ModelInfo`, `GatewayException`, `ConnectionReport`, `CheckResult`, `HttpRequest`, `Preset` and the adapter base use it; each still throws its own refusal, so no value is in a refusal made there, and its parameters are sensitive where the caller's are. | G49 | The JSON Schema validator checks standard JSON Schema only and can fetch nothing. It is built for one check, with a loader that has no resolver: a `$ref` to an `http(s)://` or `file://` address, to another file by a relative name or to a place that is not in the schema is never followed, and ends as `rejected` when an answer reaches it. A `$id` and a `$schema` are names only. The additions of `opis/json-schema` that are no JSON Schema are switched off: `$filters`, `$map`, `$globals`, `$inject` and `$slots`, `$pragma`, `$data`, URI templates in `$ref`, the filling in of `default` (it changes the answer before `required` is checked) and the decoding of `contentEncoding` and `contentMediaType` (on drafts 06 and 07 it would open PHP's file type database and keep it in a static); `$error` is not read. `format` is checked for the formats the validator knows, as it does by default. Drafts 06, 07, 2019-09 and 2020-12 are known; a schema without `$schema`, or with one the validator does not recognise as a draft, is read as 2020-12; draft 04 and a root `$id` that is no absolute address are `rejected`. The validator looks for every mismatch only when the schema holds no `$ref`, `$dynamicRef` or `$recursiveRef` (found as a name anywhere in the decoded schema, so a property of the answer with such a name counts too) and the answer holds at most 5000 values; otherwise it stops at the first mismatch, the validator's own default. When looking for every mismatch goes over the limits of one check (G52), the answer is checked a second time to its first mismatch, so a schema without references can also give only the first. At most 100 mismatches are reported, in the validator's order; when there are more, one last issue at `/` says `more mismatches are not listed: only the first 100 are reported`. Why: design section 10 names the validator but not its configuration; the library opens no connection and reads no file; `data` must be the answer as the model gave it; LR-07 asks for the reasons, not the first one, but with a reference in the schema the work of collecting every mismatch doubles with every level of the answer (a valid answer of 266 bytes took 11 seconds, one of 310 bytes more than 100), and the validator's limit on mismatches counts per object and per list, so a large answer could still hold more of them than memory (100,000 wrong items ended the process at 128 MB). | proposed |
| G50 | What the validator throws while it checks an answer. Its own exceptions, and a `TypeError` or `ValueError` raised in its own code (it raises a `TypeError` for a keyword of a wrong type such as `"type": [null]`), are the schema being wrong and become `rejected` (design section 10 step 6). Any other `\Error` is a fault in code: a new plain `\Error` with a fixed text (class, file name, line) is thrown, not chained, as the adapter base does (G40, G44). An exception that is not the validator's can only come from the host's own error handler and passes unchanged. "Its own code" is the folder of `opis/json-schema` and of the two packages it requires (`opis/uri`, `opis/string`), found by reflection on one class of each. Nothing of what was thrown is chained or copied. The detail of `rejected` is the sentence of the design, followed at most by the keyword the validator names (`…: the keyword required is not valid`), by `…: a reference in it cannot be resolved, and no other schema is ever fetched` or by `…: a reference in it leads back to itself` (G52); never a value of the schema, a path or an address. The validator reads a schema as it goes, so a fault is found only in the part of the schema an answer reaches, and never for an answer that is cut off, is not JSON or is no object (steps 2 to 4 come first). For the time of the check an error handler swallows a warning or a deprecation raised in the validator's own code and hands every other one to the handler the host had (or to PHP when it had none); every level is handed on, because PHP does not tell for which levels the host registered its handler, and `error_reporting()` is no stand-in for that (PHP calls a handler whatever it says, and PHPUnit lowers it to 245 while its own handler is in place); the host's handler is back when the check returns. In the adapter base the error takes the way of every error an adapter raises while it reads a response: not retried, with the status of the response (200) and the attempt reported as failed; a stream ends with the event "failed" after its text. Known limit: with `rejected` for a schema fault or a schema that refers back to itself (G52) the answer and its usage are lost to the caller, as with every error after a response; an answer whose check goes over its limits is returned (G52). Why: the answer is plain decoded JSON, so only the schema can make the validator throw; the text of a `TypeError` holds paths of the host; a host that turns warnings into exceptions would otherwise see an answer with a number such as `1e400` (a warning inside the validator from PHP 8.5 on) end as an error, against LR-33. | proposed |
| G51 | How the text of a structured answer is read, where design section 10 leaves it open. "Trim" removes the whitespace of JSON (space, tab, line feed, carriage return) and nothing else: a byte order mark, a no-break space or a null byte makes the answer "not JSON". A code fence is unwrapped only when it is the whole text: a first line of three or more backticks or tildes with an optional language tag that holds no such mark, and a last line with the same run of the same mark. Prose before or after the fence, a fence that is not closed, a fence closed with another length, and backticks on the line of the JSON are left as they are, so the answer is "not JSON". Nothing is repaired: text after the JSON, a second JSON value, a comment or a comma too many is "not JSON". An answer may hold 64 objects and lists inside each other; a deeper one is returned with the one issue `not JSON: nested deeper than 64 levels` (kind `not_json`, no data), not thrown. The decoder is PHP's, with no option: of a name given twice the last value counts; a whole number too large for PHP becomes a float and still counts as an `integer`; a number beyond every float (`1e400`) does not; a name that starts with a null byte is "not JSON" (PHP cannot decode it into an object). A result the adapter got its own way is kept and not checked again.
