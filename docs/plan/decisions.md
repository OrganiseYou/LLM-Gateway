# Decisions

One row per decision. Status: `decided` (by Joris, with his words), `working` (a proposal the build uses until Joris
says otherwise), `proposed` (made by the builder during a task), `open` (blocks something; a person must choose).
New rows go at the bottom with the next number. Never rewrite a `decided` row.

| G12 | HTTP goes through the library's own `Transport` interface (send, and send as a stream). The library ships a bridge to any PSR-18 client; it requires no HTTP client itself. | working |
| G13 | Structured answers are checked with `opis/json-schema`, as the OrganiseYou application does today. | working |
| G14 | Tests: Pest 4, PHPStan level 8, Pint. | working |
| G15 | "Other, OpenAI-compatible" exists as a sixteenth preset: a base URL, an optional key, a model name. | working |
| G16 | A forced tool call is its own capability (native, emulated, none). The application gets every structured answer as a forced tool call today, and the brief found a provider whose newest models refuse one. The loop asks for the final structured answer the way the capabilities allow: native structured output, a forced tool call, or the emulation of LG-08. | working |
| G17 | A short-lived sign-in token (Google Cloud, Microsoft Entra) comes from a supplier the caller gives. The caller keeps it between calls; the library keeps nothing. | working |
| G18 | A model name may hold `/`, `:` and `.` (the brief found such names at three providers). The contract checks only that it is not empty and has no control characters. | working |
| G19 | `psr/http-message` is required as `^1.1 \|\| ^2.0`, not `^2.0` only. Why: the library only calls PSR-7 interfaces and implements none, 2.0 differs from 1.1 by return types on the interfaces (release notes read 2026-11-26), and `psr/http-factory` 1.1 itself allows `^1.0 \|\| ^2.0`; a host whose other packages hold 1.x can then install the library. LG-05 changes `composer.json`. | proposed |
| G20 | Credentials are bound to the gateway object when it is built, not passed with each call. Why: LR-25 allows "per call or per client"; per client keeps secrets out of every request value and out of the five operation signatures. | proposed |
| G21 | A credential object is only the secret and how it is presented: none, bearer key, header key, bearer token from a supplier. A resource address is the gateway's base URL, a deployment name is the request's model (as LG-17 says), and a project, region or API version are named fields of the preset. Why: those words mean something at one provider only, so they stay out of the contract; LR-24 is still met (table in `docs/design/contract.md` 11.2). LG-06 builds four classes instead of the six kinds its scope lists. | proposed |
| G22 | The neutral temperature is 0.0 to 1.0 and is sent as the same number; no scaling in the contract. Why: it is the range LR-08 names as common, and a number that means the same everywhere surprises no caller. | proposed |
| G23 | A JSON Schema in the contract (tool arguments, response format) must have root type `object`. Why: tool arguments are an object, and G16 lets a structured answer travel as a forced tool call, so any other root could not be carried the same way everywhere. | proposed |
| G24 | System messages come first in a request; one after a message of another role is refused by the request. Why: every format can carry leading instructions; a system message in the middle cannot be translated the same way everywhere. | proposed |
| G25 | `stream()` never throws a gateway error: every failure, also one before the first event and after the retries, is the event "failed". Why: one code path for the caller (LR-12); LR-35 is unchanged. | proposed |
| G26 | The timeout is required on every call and is one deadline for the whole call: all attempts and all waits. A stream is covered until its end. Why: LR-36 says "per call" and the library may have no default of its own. | proposed |
| G27 | `capabilities()` sends no request; it answers from preset data and the adapter. The context length is null unless known that way; the model list gives it per model. Why: a caller asks capabilities often and must not pay a request or handle a failure for it. | proposed |
| G28 | The "provider" in an attempt report (LR-30) is the id of the preset the caller built the gateway from. It appears in attempt reports only: not in an answer, an error, a stream event or a connection report. Why: LR-30 asks for it, LR-04 and the project guide keep provider names out of what a call returns; the caller chose the preset, so it learns nothing new. | proposed |
| G29 | The message of the gateway exception is built by the library from the reason, the HTTP status, the provider code and a detail sentence the library wrote. No provider text, no chained previous exception. The provider's body reaches the host through the attempt observer only. Why: a provider's error text or a client's exception can repeat a key (LR-26). | proposed |
| G30 | A tool-result message carries the tool's name next to the call id. Why: an adapter whose format matches results by name need not search the history, and a caller always has both. | proposed |
| G31 | When the host's transport refuses a request by its own rule, the error reason is `not_configured` and nothing is retried. Why: LR-32 has no ninth reason, and an address the host does not allow is a matter of configuration. | proposed |
| G32 | The retry policy is required and has no default; the library adds no jitter. The caller gives the list of waits. Why: LR-34 gives the policy to the application; a fixed list keeps tests exact. | proposed |
| G33 | A JSON Schema built from a PHP array is read by keyword, not by array shape. The value of `properties`, `patternProperties`, `$defs`, `definitions`, `dependentSchemas`, `dependentRequired`, `dependencies` and `$vocabulary` is always encoded as a JSON object, also when its names are numbers; an empty array directly inside the first five is the empty schema `{}`; nothing under `enum`, `const`, `default` and `examples` is touched; nesting deeper than 512 levels is refused. This replaces the rule of design section 3.4 that only an empty array under six keywords becomes `{}`. Why: PHP turns numeric names into a list and cannot tell `{}` from `[]`, so the old rule sent a wrong schema without an error and a schema read back with `toArray()` did not survive. | proposed |
| G34 | A project that uses the library can connect a new LLM without waiting for a new version of the library (asked by Joris, 2026-11-26). Three cases. (1) A new model at a known provider: the model name is free text (G18); no adapter keeps a closed list of models, and for a model it does not know `capabilities()` answers with the defaults of its format. (2) A new provider that speaks a known format: the project builds its own `Preset` object in its own code (the constructor is public) or uses "other, OpenAI-compatible" (G15); a preset may state capabilities that differ from the format's defaults through `adapterOptions`. (3) A new format: the project writes its own class that extends `AbstractAdapter`, names it in its own preset, and proves it with `Testing\ContractTestCase`, which ships in the package. From the first release the constructor and the protected methods of `AbstractAdapter` are public extension points: changing them is a breaking change. Proof in the suite: a preset and an adapter defined under `tests/`, outside `src/`, pass the shared test set. Why: providers and models change faster than a library is released (LR-23 says the same for the library itself; this extends it to the caller). | proposed |
| G35 | The gateway exception removes the arguments of every call from its own trace when it is built; file, line, class and function stay. Why: PHP stores the arguments of all calls on the stack in an exception unless the host set `zend.exception_ignore_args`, and `print_r`, `var_export`, `var_dump` and `serialize` of the exception then show them in full and the string form shows their first 15 bytes; a response body, a header or a client's exception that was an argument of an adapter method would be readable there (LR-26). Design section 7.2 names the message and the previous exception only. | proposed |
| G36 | The `detail` of the gateway exception must be one line of at most 200 characters: valid UTF-8, not empty and not only whitespace, with no control character, no line or paragraph separator and no format or direction control (`[\p{Cc}\p{Cf}\p{Zl}\p{Zp}]`, so U+2028, U+2029 and U+202E are refused); otherwise `InvalidArgumentException`. A wait in seconds given with a reason other than `rate_limited` or `unavailable` is refused the same way. The provider code and the detail are sensitive parameters of the constructor, so a refused call does not keep them in the trace of that refusal. Why: the detail goes into the message and the JSON form, where a line break, a hidden character or a broken byte would break or disguise a log line, and a short limit keeps a pasted response out; design section 7.2 gives no rule for the detail and says "only with" for the wait without saying what happens otherwise. | proposed |
| G37 | `Capabilities` refuses `streaming` as `none` and `modelListing` as `emulated`; in `ModelInfo` an alias follows the same model-name rule as the id, and the name refuses control characters and invalid UTF-8. Why: design section 5.2 states the two capability facts but only the constructor can hold them now that code outside the library builds these objects (G34); an alias is meant to be usable as the model of a request, and a display name is shown to people. | proposed |
| G38 | `Secret` keeps its value as the local variable of a paused generator, not in a closure. Why: design section 11.1 suggested a closure and left it unconfirmed; tried on PHP 8.4 and 8.5, `var_dump` and `print_r` of the object cast to an array print the variables a closure holds, and reflection gives them too, while a generator shows only the name of its function in every output form, in an array cast and through reflection. A debugger that stops the process can still read the value. | proposed |
| G39 | `HttpRequest` is stricter than design section 12.2 in five places: a header name given twice in another case is refused, also inside the plain or the secret headers alone; a header name must be a string, so a name of digits only is refused; a secret header value with a line break is refused; the URL may hold only visible ASCII characters and no backslash; and the part between `://` and the first `/` or `?` must be a host of letters, digits, dots, hyphens and underscores that starts and ends with a letter or digit (an underscore is allowed because a customer's own server is often reached by a container service name such as `my_service`), or an IPv6 address in brackets, followed by at most `:` and a port from 1 to 65535. So no percent-encoding, trailing dot, second colon, empty port, open bracket or IPv6 zone in the host. The constructor takes the timeout before the body, because the body has a default and the timeout has none; the URL, both header lists and the body are sensitive parameters. Why: a PSR-7 message keeps one value per name without case, so a second one would be sent differently from what the report shows; a line break in a key is a header injection; a URL with a backslash, a control character or an encoded character in its host is read as different hosts by different clients (LR-29). | proposed |
| G40 | The PSR-18 bridge fills four gaps of design section 12.5. (1) A request the host's PSR-7 classes refuse to build is the failure `blocked` and nothing is sent. (2) Every exception of the client, of the response or of its body, also one PSR-18 does not name and also one that is not a `RuntimeException`, is `connection_failed` and is neither chained nor copied; a body that cannot say whether it has ended is broken, not complete. (3) An `Error` of the client or of its message classes (a fault in code, not a failure of the connection) never passes through: the bridge throws a new plain `\Error` with the fixed text "The HTTP client or its message classes failed with an error of class X.", not chained, so no frame of the client with the request in it survives; it is an `\Error` and not a `TransportException` so that nothing retries it and nothing maps it to a reason. An error class that implements the PSR-18 client exception stays `connection_failed`. (4) A response that breaks the rules of the library's own response (a status outside 100 to 599, a header value that is no text, an empty header name) is `connection_failed` and its body is closed; a body that gives nothing three reads in a row without ending is `connection_failed` too. Why: the refusal of a PSR-7 class can quote the header value, and the trace of anything thrown inside the client holds the request with the revealed headers (LR-26); it is the host's classes saying no (G31); a read that returns nothing for ever would hang the call where no deadline is checked. | proposed |
| G41 | The acceptance criterion of LG-05 "an observer that throws does not change the result of the call" is shown in LG-07, not in LG-05. Why: the design (12.6 rule 3, 13.4) puts the observer calls and their wrapping in the adapter base; in LG-05 nothing calls an observer, so a test there would only test a test double. LG-05 builds the observer interface, its report values and the null observer; LG-07 carries the test with an observer that throws before and after an attempt. | proposed |
| G42 | `BearerToken` does not show its supplier and is the one place that calls it; keys and tokens that a client would change on the way are refused. (1) The supplier is not a public field `$tokens` as design section 11.2 lists it: it is kept as `Secret` keeps its value (G38), and the adapter base gets a token through `BearerToken::token(): Secret`, which asks the supplier at that moment and keeps nothing. (2) An `\Exception` of the supplier is caught there and replaced by the new `Contract\Credentials\TokenSupplierFailed` (a final `\RuntimeException`, built only by the library, not chained) with the fixed text "The token supplier failed with an exception of class X."; a token that is refused under (4), and so also an empty one, gives the same class with its own fixed text. The adapter base (LG-07) catches exactly that class around `token()` and turns it into the gateway exception `credentials_rejected` of section 7.3, not retried; it does not copy the text into a detail or an event, because the class name of a host can name a vendor. (3) An `\Error` of the supplier (a fault in the host's code, such as a `TypeError`) is no failed sign-in: as in the bridge (G40) a new plain `\Error` with the fixed text "The token supplier failed with an error of class X." is thrown, not chained, so nothing maps or retries it. (4) `BearerKey` and `HeaderKey` take the key as a string in their constructor and wrap it there. A key, and a token from the supplier, is refused when it is empty, holds a byte below 0x20 or the byte 0x7F (so a line break, a tab, a null byte), or starts or ends with a space; bytes 0x80 to 0xFF are kept. The refusal never holds the value. Why: the supplier is the host's class and may hold a client secret or a kept token in a plain property, which every dump of the credential (and of a gateway that holds it) would print (LR-26); its exception can hold the token in its message and its trace, so it must not get past the one call site; a broad catch in the adapter base could swallow a gateway or transport exception, a dedicated class cannot; PSR-7 message classes trim a header value, so a key with a space at its end would be sent without it while `secrets()` gave it with it, and the host's redactor would then miss the key in a log; the design gives the fields but no constructor and no validation. | proposed |
| G43 | The pattern of a preset field is a regular expression without delimiters, and the library anchors it: a value must match from its first to its last character. A value that fills a `{key}` placeholder of the default base URL must besides hold only letters, digits and `. _ ~ -`, whatever its pattern allows, may not be `.` or `..`, and the filled address is checked again as an address; otherwise `not_configured`, naming the key. A preset is refused when a placeholder in the host of its default base URL is not followed, after at most the rest of its label, by a dot and a fixed domain of two labels or more: `https://{resource}.example.test/` and `https://{region}-api.example.test/` are allowed, `https://api.example.test{x}`, `https://{x}/v1` and `https://{x}.test` are refused, so a setting can never choose the registrable domain. A required field with an empty value counts as missing. Why: design section 13.1 says "a regular expression the value must match" and relies on the pattern alone; a pattern without anchors would let a setting such as `other.example.org/` move every request to another host (LR-29), and a preset can be written outside the library (G34). | proposed |
| G44 | The adapter base differs from the sketch of design section 13.4 in these places (the section allows it). (1) It is an abstract readonly class with a final constructor, so every adapter is readonly and is built the one way the factory builds it; the five checks of section 13.3 run in that constructor (through `GatewayFactory::resolveBaseUrl`), so a gateway built without the factory is checked the same way. Credentials of a class other than the four of the library are refused there as `not_configured`: the base could not send them. (2) An adapter reaches the preset (`$this->preset`) and one setting of the customer by its key (`setting()`); the configuration with the clock, the observer and the retry policy, the credentials and the transport are private to the base. (3) `capabilities()` is final and checks the model name; the adapter writes `modelCapabilities()`. (4) `completionRequest()` and `modelsRequest()` give the request without sign-in; the base adds the sign-in header and the time left for every attempt, and refuses (a `LogicException`, nothing is sent) a request whose address does not start with the resolved base URL. `modelsRequest()` gives null where the models cannot be listed. (5) An adapter builds its answer with `answer()` and its own errors with `failure()`; the base fills in the trace id, the attempts, the status, the latency and the structured result, also for an error raised in `modelCapabilities()`. An error an adapter raises while it reads a response is never retried. A provider code or a detail that holds a credential anywhere in it (a key of `secrets()` or the token in use, compared without case) is dropped whole. (6) `retryAfterSeconds()` is a third hook next to `providerCode()` and `refineReason()`, for a wait a format documents outside the `Retry-After` header. (7) An exception an adapter throws while it reads a response becomes `provider_error` with a fixed detail; while it reads a failed response it means "no code, no wait, the reason of the status". An `\Error` there, and a value from `readStream()` that is no stream event, is a fault in code: the attempt is reported as finished, then a new plain `\Error` with a fixed text (class, file name, line) is thrown once, not chained, as in the bridge (G40). (8) The structured check of section 10 is not a hook: its place is marked in the base, which will call the checker itself; an adapter that gets the structured answer its own way hands the result to `answer()`. Why: the request value needs a timeout and secret headers that only the base knows per attempt; a readonly class cannot keep state between calls (LR-01); what an outside adapter can reach is a promise from the first release (G34), so it is kept small; the exception of an adapter can quote the body it could not read, and its trace holds that body, and a provider can repeat a key inside a longer code (LR-26). | proposed |
| G45 | Details the design leaves open, as built. A status below 200 is `provider_error`, not retried. A stream that fails after the response began carries the status of that response in its error. The deadline of a stream is checked when a chunk arrives: a chunk that arrives after it ends the stream as `timeout`, also when it would have been the last. A wait from the provider counts for `rate_limited` and `unavailable`; in the error it is rounded up to whole seconds and capped at 2147483647. `Retry-After` is read as seconds (a fraction is accepted) or as an IMF-fixdate that exists (31 February is not rolled over); any other form is treated as not given. A token supplier is asked after the check that time is left, and its time counts against the call. The time left for an attempt is computed before the "before" report, so a slow observer can make a call overrun by its own time. An attempt of a stream that the caller abandons is reported as succeeded, with what was read. An exception of a transport that is not a `TransportException` passes unchanged, after the attempt is reported as a transport error (`connection_failed`, no retry). Known limit: the bytes of a stream are kept whole for the report of the attempt (section 12.6), without a cap on their size; only the deadline bounds them. Why: each is the reading that keeps the eight reasons and the "retried" column of section 7.3 unchanged. | proposed |
| G46 | The event reader gives an event that is not closed by a blank line when the body ends, and takes a last line without a line end as a line. Bytes that are not valid UTF-8 become U+FFFD, one per byte. Why: the WHATWG text (HTML, section 9.2.6, read 2026-11-26) lets a browser drop an unfinished event because a browser reconnects; here a body that ends is complete (a broken connection is an exception of the transport) and a server that leaves out the last blank line would lose its last event, usually the one that ends the answer; the events must be valid UTF-8 because the answer text must be. | proposed |
| G47 | An answer without text and without a tool call is returned as an answer when its finish reason is the token limit, with its usage; with any other finish reason it stays `provider_error`. This changes the row "with no text and no tool call" of design section 7.3 and the sentence of 4.4 that such an answer never becomes an `Answer`: `Answer::toMessage()` still refuses it. Why: a model that spends every token before any output is a normal case, and the structured check must be able to report it as "cut off at the token limit" with its reasons instead of an exception (LR-33, LR-07). | proposed |
| G48 | The rules that several values share (trace id, model name, provider code, timeout, HTTP token) are written once, in `Contract\Internal\Rules`: a final class with static methods that only answer yes or no (or give the cleaned code), marked `@internal`, without state. `Request`, `Answer`, `ModelInfo`, `GatewayException`, `ConnectionReport`, `CheckResult`, `HttpRequest`, `Preset` and the adapter base use it; each still throws its own refusal, so no value is in a refusal made there, and its parameters are sensitive where the caller's are. Why: the same pattern stood in up to five classes; the design's class table does not list this class, and it is not part of the contract. | proposed |
